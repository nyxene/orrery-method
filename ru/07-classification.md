## Четыре оси · *Rule*

Ось отвечает на один вопрос, и item несёт не больше одного её значения — за единственным исключением оси flags, где каждый flag есть собственный независимый факт. Ось зарабатывает своё место, отвечая на вопрос, который действительно задают, или выбирая поведение ниже по потоку; ось, не делающая ни того ни другого, — украшение со стоимостью сопровождения.

| Ось | Вопрос | На item | Кто читает |
|---|---|---|---|
| type | Что это за вещь? | Ровно одно | Маршрутизация, каждый запрос, exclusivity check |
| area | Какая часть системы? | Не больше одного | Пакетирование — «то ли это место, где я уже нахожусь» |
| priority | Отклоняется ли срочность от нормы? | Не больше одного; отсутствие значит норму | Owner, упорядочивая работу |
| flags | Какой сквозной факт держится? | Каждый flag независим | Запросы; `needs-owner` и `triage` — Owner |

![Четыре оси: type ровно один из шести, area не более одной, priority не более одного из трёх, flags любое число из четырёх.](../diagrams/ru/axes.svg "Одна ось отвечает на один вопрос. Больше одного значения допускает только ось flags, потому что каждый flag — независимый факт, а не выбор между альтернативами.")

> [!WHY]
> Классификацию ограничивает стоимость выбора, а не хранения — и платит её агент с холодного старта, для которого список значений — весь путеводитель. Одно значение на ось держит каждый выбор маленьким: взять один из шести types, одну из нескольких areas — и готово. Откажитесь от этого — и вопрос становится «какое подмножество из двадцати применимо», на что ни имя, ни описание надёжно не отвечают.

Пятой оси нет. Статус выводится, размер отвергнут, потому что измеряемый ресурс — токены, последовательность живёт в releases, а команд, между которыми маршрутизировать, не существует.

Как значение оси записано физически — метка, поле, нативный тип — забота трекера, и [Привязки](10-mapping.md) решают это по каждому трекеру. Ничто в этом документе от ответа не зависит.

## Маршрутизация · *Rule*

Каждый кусок работы направляет routing test, задаваемый в двух масштабах: **отгрузится ли X без этого?** Спрошенный о feature, ответ «нет» делает это task под ней. Спрошенный о release, «нет» втягивает item в этот release — по слову Owner, потому что «что блокирует поставку» — его вопрос.

Всё остальное не имеет дома вовсе. Дом — это обязательство, а не картотека: членство в release утверждает «это отгружается вместе», item, который не утверждает ничего, не несёт членства — умолчание несёт отсутствие, — а запрос по type и area находит item, где бы он ни находился.

Членство отвечает, что было обещано и что блокировало. Что реально отгрузилось — собственная запись репозитория на теге, и changelog выводится из мержей — никогда из членства.

| Вид работы | Объект | Type | Дом |
|---|---|---|---|
| Любой исход, разложимый | Feature | feature | Release, когда Owner её закоммитил; ничего, пока ждёт |
| Один пулреквест исхода | Task | task | Release её feature |
| Дефект в отгруженном поведении, один пулреквест | Flat item | bug | Нет — или release, который не может отгрузиться, пока это живо |
| Дефект, чьё исправление требует больше одного | Feature | feature | Release, когда Owner её закоммитил |
| Уход без изменения поведения | Flat item | chore | Нет |
| Вопрос, требующий ответа | Flat item | research | Нет — блокирует связью, никогда членством |
| Изменение только документации | Flat item | docs | Нет — если только feature не может без него отгрузиться, что делает его её task |
| Инфраструктура | её настоящий type | + area infrastructure | По своему type |
| Безопасность | её настоящий type | + flag: security | По своему type |
| Дефект внутри boundary открытой task | не item | — | Пулреквест той task |

Тест старше таблицы. Её строки — умолчания для работы, на которую никто не претендует; в момент, когда feature или release не могут отгрузиться без item, тест сказал своё, а строка — нет.

Инфраструктура — место, а не вид: сбой конвейера — это bug в area infrastructure. Безопасность пронизывает каждый вид — уязвимость это bug, укрепление это feature, — поэтому она flag поверх настоящего type и никогда не type, борющийся за слот. Type, который на деле area, flag или priority, сталкивается со своей осью в первый же раз, когда истинны оба утверждения, и каждое оформление после этого решается произвольно.

Именно поэтому «отложенный беспорядок» не является type: отложенность — это говорит ось priority, а сам беспорядок есть bug, chore или task, как и всё прочее.

Дефект, слишком крупный для одного пулреквеста, — не одна единица работы, и заведение его как одной не заставит его туда поместиться. Он проходит framing, как всякий другой goal, и становится feature, чьи tasks — шаги починки, неся строки `Origin` и `Escaped` — написанные один раз, на этом framing, тем, кто оформляет починку, поскольку дефектная строка к тому моменту уже известна, — и ни одна task их не меняет. Census считает по тем, кто несёт эти строки, а не по тем, кто несёт type, так что дефект, починенный как feature, посчитан один раз, в правильном месте, и второго дома для него не выдумывают.

Bug, оказавшийся не дефектом, не заставляют закрыться как дефект. Вопрос, который он на самом деле задавал, — верно ли это поведение — получил ответ, поэтому он становится research — его переводит в этот type party, нашедшая ответ, и она пишет, где ответ будет записан, прежде чем писать сам ответ, — и закрывается им. Ничего не выдумывается, чтобы заполнить строку `Origin`, за которой нет коммита.

Research-item — это вопрос. Он называет, где будет записан ответ, и закрывается, когда ответ существует, — вливался ли при этом какой-нибудь пулреквест или нет; research, который должен предшествовать feature, блокирует её связью зависимости и никогда вложенностью, потому что research, заключивший «не строить», — удался.

Расследование, порождающее работу, — это тот же research-item: аудит, разбор, проход ревью. Найденное оформляется плоскими items со ссылкой назад на него и никогда не его детьми: расследование ничего не отгружает, поэтому у routing test на нём нет ответа, а вложенность обещала бы поставку, которой никто не обещал. Что от него осталось — это запрос по этим ссылкам, а не rollup.

Работа, настоящая лишь при условии, ждёт со строкой **Trigger**, называющей это условие, — оформленная, бездомная и нетронутая, пока условие не наступит. Trigger называет наблюдаемое условие — в том же смысле, в каком goal называет наблюдаемое конечное состояние: что-то способно ответить, наступило ли оно. Item, чей Trigger никто не может назвать или никто не может вычислить, — не ждущая работа: это либо работа сейчас, либо ничто.

## Bug называет своё происхождение · *Rule*

Bug несёт в теле три строки, каждую пишет свой автор в свой момент.

| Строка | Называет | Пишет | Когда |
|---|---|---|---|
| Found-in | Где всплыл — продакшен, чтение, аудит, проход Planner. Свободная проза, не управляемая ось | Тот, кто оформил | Оформление |
| Origin | Task или пулреквест, отгрузившие дефект | Executor, который чинит; тот, кто оформляет feature починки | Починка; framing feature починки |
| Escaped | Проверка, которая пропустила, — framing test или одна из четырёх stations, которые называют [Роли](02-roles.md) | Executor, который чинит; тот, кто оформляет feature починки | Починка; framing feature починки |

Origin и Escaped пишутся в момент починки, потому что executor и так стоит на дефектной строке, а цепочка оттуда механическая: история репозитория называет коммит, коммит — свой пулреквест, пулреквест — свою task и feature.

Bug не закрывается без строки Origin — заполненной или честно нет: *predates the method*, *interaction* с двумя ссылками, *unknown*. Ложная точность хуже записанного пробела, а Escaped работает и без Origin: природа дефекта называет пропустившую проверку, даже когда коммит не найден.

> [!WHY]
> Эти три строки делают ретроспективу механической, а не археологической. А обратная половина не стоит ничего там, где привязка поставляет зеркалируемую ссылку: закрытая feature тогда накапливает летопись того, что оставила за собой, — выводимо, никогда не поддерживаемо.

## Метка — это ось, ссылка — это факт · *Rule*

Метка несёт значение из малого закрытого набора, который запросы читают постоянно. Ссылка несёт факт между двумя items — происхождение, блокер, замещение.

Закодируйте факт меткой — по метке на каждую feature, когда-либо отгрузившую bug, — и ось теряет потолок: набор растёт с историей, а не с системой, и каждое будущее оформление платит стоимость выбора по всему списку. Факт, закодированный меткой, — ось без потолка; ось, закодированная ссылками, — запрос, которого не существует.

## Значения · *Rule*

Ось type зафиксирована шестью значениями выше. Ось area определяется проектом: каждое значение называет место, на которое можно указать — значение, чьи каталоги нельзя назвать, это тема, а темам место в заголовках, — и ось ограничена восемью значениями.

У оси priority три значения и нет середины: *critical* вытесняет task in flight, *high* идёт раньше нового охвата в той же area, *low* ждёт, пока что-то уже не окажется в том же файле. Значение со смыслом «умолчание» ставится на большинство items и не читается никем, поэтому умолчание несёт отсутствие.

Два трекера были посчитаны против этого правила, и оба применяли среднее значение — по 28 раз — до того, как правило существовало. По правилу [Инвариантов](05-invariants.md) об истории до правила эти счета описывают умолчание, которое эта ось убирает, а не потребность, которую она отрицает; первое среднее значение, поставленное *под* правилом, было бы тем контрпримером, которым эти не являются.

Flags четыре. Flag *security* помечает изменение защитной позиции, а flag *unread-exempt* — закрытие, которое до очереди Owner не доходит вовсе; тем, какие потоки подходят, владеет [Цикл](04-cycle.md).

Flag *needs-owner* помечает работу, вставшую на суждении, которое может вынести только Owner, — единственный факт, который не выразит связь зависимости, потому что указать не на что.

Flag *triage* помечает item, который агент оформил по собственной инициативе и оставил. Owner читает эту очередь, указывает, и агент снимает flag действием — так пропуск остаётся видимым в запросе, а не исчезает.

Discovery, сделанная сразу после своей task, triage не несёт: её evidence дойдёт до Owner через очередь unread.

## Первые слова классифицируют · *Guide*

Первые слова формулировки называют её type. Агент, оформляющий работу, сверяет собственные первые слова с этой таблицей раньше всего остального.

| Начинается как | Type | Реальное начало |
|---|---|---|
| «Дать возможность…» — что становится возможным | feature | "Compare two charts side by side" |
| «Добавить / изменить / провязать X в Y» — одно изменение, одно место | task | "Render two wheels side by side" |
| «X делает Y, ожидалось Z» — отгруженное поведение, пошедшее не так | bug | "South Node glyph displaced ~176px" |
| «Обновить / ротировать / перегенерировать / почистить» — уход, поведение не тронуто | chore | "Swap the plugin source to GitHub" |
| «Как / какой / стоит ли…» — вопрос | research | "Which mechanism can switch Caddy upstreams?" |
| «Проверить / доказать / замерить X» — установить факт о системе | research | "Verify SOURCE_COMMIT resolves to a real SHA post-deploy" |
| «Описать / поправить описание…» — проза о системе | docs | "The README claims isolation the config does not enforce" |

Глаголы — образцы, не забор: совпадать надо с сутью в середине строки, никогда с буквой. Формулировка, совпавшая с двумя строками, — два неразделённых item; не совпавшая ни с одной — незаконченный framing, и в обоих случаях решает правило маршрутизации, а не эта таблица.

## Управление · *Rule*

Добавление дорого, удаление дёшево — по замыслу. Новое значение замещает существующее в своей оси; новая ось замещает ось. Единственное исключение — ось area: она растёт без замещения, пока кодовая база отращивает действительно новую часть, до потолка.

Агент никогда не изобретает значение по собственной инициативе. Набор значений — интерфейс, который читает каждая последующая session, поэтому его расширение — решение Owner; агент, которому набора не хватило, оформляет случай под flag needs-owner и ждёт.

Изъятие — ответ на сомнение по умолчанию. Удаление значения оставляет его items в остальном нетронутыми, а восстановление — одно действие, поэтому раннее изъятие не теряет ничего.

Census — им владеет [Автоматизация](09-automation.md) — несёт половину этой оси: значение с нулём применений за всю жизнь удаляется и докладывается, решать там нечего, а значение, применённое меньше десяти раз, докладывается кандидатом на следующее замещение — это слово Owner.
