## С чего начать

Метод — это текст. Взять его в работу значит делать то, что в нём сказано, а не что-то устанавливать. Проект, который хочет начать, делает пять шагов, по порядку.

1. **Назвать Owner.** Один человек, чьё внимание решает всё, что метод оставляет человеку. Без него остальному методу некому отчитываться — начните с [Ролей](02-roles.md).
2. **Выбрать трекер и привязать его.** Артефакты живут в том трекере, которым проект уже пользуется. [Привязки](10-mapping.md) говорят, какой его объект несёт feature, task и evidence package.
3. **Укомплектовать места.** Решить, кто или что держит каждую accountability, не нарушая separations: никто не проверяет собственную работу. Одна из комплектаций — в [Agents](12-agents.md).
4. **Заставить gates работать самих.** Проверка, которая запускается, когда кто-то вспомнил, — не gate. Какими бы ни были проверки проекта, они идут на каждом изменении без просьбы.
5. **Провести один item из конца в конец.** Как это выглядит — в [Сценариях](11-playbooks.md). Одна feature, доведённая от wish до слияния, учит больше, чем ещё одно прочтение.

Проект может взять нужные части и оставить остальное. Чего он не может — взять части и оставить себе имя.

## Orrery, один инструмент, который следует методу

[Orrery](https://github.com/nyxene/orrery) — плагин для Claude Code, написанный, чтобы следовать этому методу. Это один из способов укомплектовать места из [Agents](12-agents.md) инструментами, не единственный, и метод его не требует.

| Что требует метод | Что даёт Orrery |
|---|---|
| Framer | skill `frame` — смутное wish становится сформулированной целью через вопросы, до всякого планирования |
| Planner | skill `plan` — план, составленный до того, как что-то потрачено |
| Critic, plan ruling | агент `critic`, а когда неясен сам подход — вместе с агентом `architect` |
| Implementer | skill `build` — утверждённый план, исполненный агентами, с аудитом перед каждым коммитом |
| Gates | guards, которые отказывают в разрушительных командах, рядом с собственными pre-commit и CI проекта |
| Auditor, verification | агент `auditor` — свежая сессия, на модели другого семейства, чем у implementer, если бюджет позволяет |
| Owner | остаётся человеком: Orrery не держит слияние ради него, а Owner читает то, что слито, — последняя station метода |
| Handoff | skill `handoff` — то, что сессия узнала, переносится через сброс контекста |

Это соответствие — утверждение Orrery о самом себе. Где Orrery и метод расходятся, обязывает метод, а расхождение — дефект инструмента.
