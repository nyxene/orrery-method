## Термины {rule}

Один термин, одно значение, одна строка. Документ, использующий слово из этой таблицы, использует его ровно в этом смысле; документу, которому нужен другой смысл, нужно другое слово.

| Термин | Значение |
|---|---|
| item | Одна запись в трекере: feature, task или плоская. Как её зовёт трекер — issue, work item — забота [Привязок](10-mapping.md) |
| release | Именованный набор работы, который отгружается вместе. Закрывается по слову Owner, актом агента, когда содержимое отгружено и на нём лежат census и вердикт conformance — этим переходом владеет [Автоматизация](09-automation.md); никогда не отрезок времени |
| feature | Поставляемый исход и план, как его достичь. Владеет tasks. Исход, а не функция продукта — переработка документации и проход по укреплению суть features |
| task | Один пулреквест работы под feature. Та же единица без feature над ней — flat item |
| flat item | Item без родителя. Бездомен и находится запросом — если только release не может отгрузиться, пока тот жив |
| bug | Дефект в отгруженном поведении |
| chore | Уход без изменения поведения |
| research | Вопрос. Закрывается, когда ответ существует там, где item обещал его записать |
| docs | Изменение только документации |
| wish | То, чего Owner хочет, — до того, как кто-либо сформулировал, что его удовлетворит |
| goal | Одно предложение, называющее наблюдаемое конечное состояние. То, что производит framing |
| acceptance criteria | Наблюдаемые выходы, по которым судят task. Эквивалент у feature — её `Ship condition` |
| boundary | Что item заявляет трогать и чего касаться отказывается. Дифф остаётся внутри |
| primitive | Одно структурное средство трекера — вложенность, связь, классификация, состояние |
| accountability | Именованная ответственность за решение. Не наём |
| station | Проверка, которую поток обязан пройти, у party, независимой от проверяемого |
| party | Тот, кто занимает accountability или station. Человек, агент, несколько |
| separation | Пара, которую метод запрещает. Три — про party по обе стороны проверки; четвёртая — про контекст: station никогда не проходится в той session, которая произвела то, что она судит |
| executor | Party, исполняющая одну task |
| verifier | Party, проверяющая изменение, которого не писала, до мержа |
| plan ruling | Вердикт party, не писавшей план, вынесенный до затрат |
| closing agent | Party, чьим актом закрывается единица работы: executor, вливающий мерж или совершающий акт, исследователь, дающий ответ, verifier, выносящий отказ, или агент, закрывающий по слову Owner. У контейнера closing agent нет — feature закрывает party, чьим актом она опустела, release — агент, действующий по слову Owner |
| execution profile | Кто или что занимает каждую accountability и station в конкретном проекте. [Agents](12-agents.md) — один из них |
| session | Один непрерывный заход одной party в один кусок работы. Что не записано — его не переживает |
| gate | Скриптовая проверка, которая блокирует или выполняет, — машинерия, никогда не память |
| cold-start test | Способна ли session без всякого другого контекста это исполнить? Task готова, только если да |
| routing test | «Отгрузится ли X без этого?» — спрошенный о feature даёт tasks, о release — членство |
| discovery | Работа, замеченная во время другой работы: оформляется и делается следующей |
| finding | То, что verification докладывает по одному изменению. У него три диспозиции — исправлено здесь, оформлено своим item или отвергнуто. Ими владеет [Цикл](04-cycle.md) |
| evidence package | Шесть именованных строк — Item, Built, Decided, Checks, Parties, Result — и дописанный verifier Verdict. Формой и моментом владеют [Артефакты](03-artifacts.md) |
| ledger | Дозаписываемая летопись расхода, рядом с которой лежит датированная таблица цен. Единицей, полями и автором владеет [Измерение](08-measurement.md) |
| handoff | Осадок session — уже испробованные и отброшенные подходы, записанные комментарием на task |
| standing instructions | Собственные письменные правила репозитория для каждой session — единственный вход executor помимо item |
| framing | Переход от wish к goal |
| rollup | Выводимый счёт закрытых детей feature против всех её детей |
| in flight | Task, над которой party работает прямо сейчас |
| review mark | Момент закрытия новейшего item, чей evidence package Owner прочёл; записывается раз на проход чтения агентом, действующим за него, и никогда не перезаписывается |
| unread | Закрыто после review mark — evidence package ещё не прочитан Owner |
| consistency check | Проверка, выносящая вердикт по восьми инвариантам и по исключительности каждой оси |
| exclusivity check | Проверка, перечисляющая items со вторым значением на одной оси |
| census | То, что closing agent запускает на закрытии release. Списком владеет [Автоматизация](09-automation.md) |
| incident | Работа, вытесняющая то, что in flight, — по слову Owner либо по слову обнаружившего агента с `needs-owner`, пока Owner не вынесет своё |
| effort | Глубина рассуждения, на которой шёл прогон; пишется в ledger, чтобы объяснять дисперсию, — никогда чтобы считать стоимость |
| Found-in · Origin · Escaped | Три строки, которые несёт bug: где всплыл, что его отгрузило, какая проверка пропустила |
| Trigger | Условие, превращающее ждущий item в настоящую работу; заявляется на item при оформлении |
| Owner · Framer · Feature Lead | Три accountabilities. Определениями владеют [Роли](02-roles.md) |
| Planner · Critic · Implementer · Auditor | Каст профиля [Agents](12-agents.md) — комплектация, никогда не accountabilities |
| Rule · Principle · Guide | Ярусы силы. Ими владеет [Обзор](01-overview.md) |
| standing | Подтвердила ли практика раздел: *Proven*, если через него без изменений прошла отгруженная feature, *Pending*, если нет. Независим от силы — Pending Rule обязывает ровно так же, как Proven |
| refusal | Третья диспозиция verification: изменение делает то, о чём просили, а просили неверно. Пулреквест закрывается без мержа, а task закрывается с исходом `refused` |
| conformance | Шесть утверждений, которые проект держит, чтобы притязать на метод. Ими владеет [Обзор](01-overview.md) |

## Термины не переводятся никогда {rule}

Английский термин — идентификатор, на любой локали. Проза вокруг может быть на любом языке; само слово не меняется, и читатель любой локали встречает ту же строку, которую используют запросы, классификации и остальные локали.

Имена строк, которые несёт item, — термины ровно этого рода: `Goal`, `Framed`, `Out of scope`, `Decided`, `Tasks`, `Planned`, `Ruling`, `Ship condition` у feature; `Item`, `Date`, `Outcome`, `Retries`, `Runs` у строки ledger; `Found-in`, `Origin`, `Escaped`, `Trigger` у items, которые их несут. Они стоят в телах дословно, на любой локали, потому что тело — это то, что греппают.

> [!WHY]
> Переведённый термин — второе имя одного объекта, а два имени расходятся так же, как две копии любого факта. Одно из них тогда проваливает поиск, который проходит другое, и о промахе никто не сообщает.
